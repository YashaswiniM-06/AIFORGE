# PackSignal visual and market-review enhancements

This build adds several review aids around the original proof chain:

- **Artwork check coverage:** Located artwork evidence is shown directly on the rendered page. Green means a supported comparison matched; amber means human review; red means an issue. Uncolored areas have no located check. It is deliberately described as coverage, not model confidence or release readiness.
- **Visual copy comparison:** When an issue has a precise artwork region, the source reference is shown beside the original artwork in green and the observed region in red. The source label is not an approved correction and never edits the artwork.
- **Revision viewer:** Original rendered artwork versions are shown side by side with synchronized scrolling. The underlying check table remains the auditable record of the change.
- **Guided walkthrough:** A first-time tour opens the organizer files and explains outcomes, evidence, coverage, source authority and exports.
- **Optional market starter checklists:** US, India and EU selections add text-cue review prompts linked to official primary sources. They are not legal advice, complete rulesets, or a compliance determination.
- **Language and code signals:** Multiple packaging cues can flag Spanish, French, Hindi or Arabic text for translation review. A local scanner records detected code type and approximate location without storing payloads or following links. A lack of detection is always *Unable to verify*, never evidence that a code is absent.
- **Exact bilingual copy pairs:** A structured reference can provide source-approved, required wording for each language. PackSignal checks those exact phrases against the artwork and connects each phrase to source and artwork evidence. Missing wording stays unverified until a reviewer confirms source authority and artwork coverage. The check does not translate or decide semantic equivalence.
- **Sibling-SKU catalog screen:** Clearly tabular spreadsheets with recognizable SKU, variant, ingredient, allergen, quantity or barcode columns can reveal artwork strings that belong to a different product row. The result points to both spreadsheet cells and artwork evidence; a reviewer decides whether it is carryover or intentional cross-promotion.
- **Environmental-claim evidence prompt:** Common packaging sustainability terms are surfaced for claim-specific review. A text reference in the claims register is not treated as proof that a certification or substantiation supports the exact material, wording, package and market.
- **Lower-front position guide:** If a reviewer maps the Front panel and net quantity is located, the artwork map marks the lower 30% of that reviewer-drawn zone. It is a geometric prompt only; PackSignal does not infer a statutory display panel or decide whether a placement rule applies.
- **Portable HTML report:** Findings, quotes, decisions, source hashes, revision history and reduced artwork renderings can be exported as one self-contained file. It has no external scripts, fonts or network dependencies.
- **Prepress screening:** Located PDF text regions report approximate physical height in millimeters and points against a reviewer-selected screening value. Because text extraction measures bounding boxes and not glyph height or final print scale, every result remains a human review prompt.
- **Panel-zone mapping:** Reviewers can draw Front, Back, Left, Right, Top and Bottom rectangles over rendered artwork pages. Located rule evidence is checked geometrically against the selected zone; unmapped rules remain human review. A drawn zone does not determine legal display-panel definitions or automatically recognize cut and crease lines.
- **Review-stage stepper:** Sources and authority, compiled checks, artwork verification, and the audit report are linked from the review header. Open source decisions and issue counts are shown from the current review; the stepper says the seal is created on export until one exists.
- **Prepress HUD:** The 2D viewer reports pointer coordinates in millimeters for PDF page geometry, exposes zoom and evidence/panel-zone layers, and recomputes the uploaded source SHA-256 in the browser against the stored extraction hash. Raster-image inputs show normalized coordinates because their physical print size is unknown.
- **Proof spotlight and trace connector:** Opening a finding centers the artwork region in an adjustable zoom view with surrounding artwork dimmed. A local SVG connector links source evidence to the located artwork region in the proof dialog.
- **Mapped carton context:** The 3D fold context can be dragged, rotated with a control, and decorated with selectable finding pins. It maps reviewer-defined rectangles to an approximate six-face cuboid. It does not recover structural CAD, score lines, glue flaps, board caliper, or stock weight from a flat image.
- **Allergen and nutrition checks:** Uppercase and `CONTAINS` text cues prompt allergen inspection. Internal nutrition screens compare calories with a simple 4-4-9 estimate, sugars with carbohydrates, saturated fat with total fat, and servings with net quantity when compatible source values exist. They surface inconsistencies for confirmation and do not establish regulatory compliance.
- **Finding actions:** A located finding can produce a copyable agency change request with its page, approximate normalized box, observed copy and source quote. Optional Gemini follow-up questions receive only the selected finding and its evidence; questions and answers are retained in the review record.
- **Actionable change request:** Tickets identify the observed text, supplied reference, page and approximate location, then ask the designer to confirm the applicable approved copy. They do not invent a font, point size, Illustrator layer name or legal correction when the sources do not provide one.
- **Signed report seal:** PDF, JSON and HTML exports receive an Ed25519 signature over source hashes, finding evidence, reviewer decisions and audit digest. The keypair stays in the local review-data directory. Verification detects edits relative to that local key; it does not provide independent identity proof or protect against a person who controls the machine and signing key.
- **Portable verification:** HTML and JSON exports carry the canonical signed payload and can be checked offline with `node scripts/verify-report.mjs`. The PDF prints its signature and fingerprint; use its matching HTML or JSON file for programmatic verification. Trust the signer fingerprint out of band.
- **Regression checks:** `npm test` runs a zero-dependency Node suite for quantity conversions, text normalization, revision transitions, panel geometry, nutrition screens, allergen cues, HTML report contents, report-signature tampering, mocked Gemini retry/quota behavior, and multi-batch image coverage.

## Validation boundary

The language and code demo uses original fictional Fieldday artwork. Its Spanish and French copy is explicitly unapproved, and its Code 128 and QR payloads are fictional. Detection proves only that the generated scanner path recognized symbols in that controlled example. It does not validate barcode print quality, retail assignment, translation accuracy, full regulatory applicability or production artwork. Exact bilingual parity requires a separate source file with approved required wording for each language.

The new bilingual exact-copy path is regression-tested with synthetic paired strings; it has not been independently reviewed by a translator. The market regex regression tests prove cue recognition on constructed text, not legal-rule coverage.

## Scope of the added checks

Text height uses the extracted PDF text bounding box and page dimensions, which can differ from printed glyph height after imposition or scaling. The displayed threshold is reviewer-selected. Allergen formatting checks only uppercase and explicit `CONTAINS` cues; boldness and all jurisdiction-specific allergen rules remain visual-review items. Nutrition checks are simple internal consistency screens and require comparable units and serving bases. Panel zones are user-drawn rectangles on a rendered page. Sibling-SKU scanning needs a recognizable tabular schema and can flag intentional shared copy. Environmental detection uses a bounded phrase list and does not authenticate references in a claims register. Exact bilingual checks only compare the user-provided phrase pairs, not meaning or translation quality. The lower-30% guide is measured only inside a user-drawn front rectangle. Signed exports are verifiable against the signing key stored on the same local machine; share the public key separately if independent verification is needed.
